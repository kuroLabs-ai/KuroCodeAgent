# KuroCode

## Product Requirements Document — PRD

**Project:** KuroCode
**Product Type:** Local-First Autonomous AI Agent / Personal Computer Agent
**Primary Platform:** Windows
**Primary Language:** Python
**Primary Interface:** CLI / Console
**Architecture:** Modular, Local-First, Provider-Agnostic, Tool-Driven, Extensible
**Status:** Architecture & Development Planning

---

# 1. Product Vision

KuroCode is a personal AI agent that lives on the user's computer.

Instead of being only a chatbot, KuroCode should be able to:

* Understand the user's goals.
* Understand the computer and current environment.
* Reason using one or more LLM providers.
* Execute actions on the PC.
* Read and modify files.
* Run CMD, PowerShell, and Python.
* Work with Git and development projects.
* Use external APIs and services.
* Remember relevant information.
* Install and use tools/plugins.
* Recover from failures.
* Diagnose and repair problems.
* Automate recurring tasks.
* Improve its capabilities in a controlled way.
* Maintain an identity and configurable personality.
* Operate primarily through a CLI.

### Product one-liner

> **KuroCode is your personal AI agent living inside your computer.**

### North Star

One intelligent CLI agent that understands the user's goal and computer, chooses the right tools, executes work, observes results, recovers from failures, remembers context, integrates with external services, and safely expands its capabilities.

---

# 2. Problem

Developers and power users currently switch between many different applications:

* ChatGPT
* Gemini
* Claude
* VS Code
* Terminal
* CMD
* PowerShell
* Git
* GitHub
* Browser
* Google Drive
* Email
* Discord
* Telegram
* APIs
* Cloud services
* File Explorer

The user has to manually move information between these systems.

KuroCode aims to unify these capabilities into one agent.

Instead of:

> Ask AI → copy answer → open terminal → run command → inspect error → return to AI → copy fix → edit files → run tests → commit

The goal is:

> **Tell KuroCode the goal and let the agent handle the workflow.**

Example:

```text
kuro> Analyze this project, fix the errors, run the tests,
      and commit the changes.
```

KuroCode should be capable of planning and executing the workflow.

# 3. Product Principles

## 3.1 Local First

KuroCode should operate primarily on the user's machine.

The local machine is the agent's environment.

---

## 3.2 Provider Agnostic

KuroCode must not depend on a single LLM provider.

Possible providers include:

* Gemini
* Groq
* OpenAI
* Anthropic
* OpenRouter
* Ollama
* Custom providers

The agent should be able to switch between providers.

---

## 3.3 Tool Driven

The LLM should not directly control the computer.

Instead:

```text
LLM
 ↓
Decision
 ↓
Tool
 ↓
Execution
 ↓
Result
 ↓
LLM
```

This makes actions observable, testable, permission-controlled, and replaceable.

---

## 3.4 Modular

Every major subsystem should have a clear responsibility.

Examples:

```text
Brain
Memory
Tools
Security
Plugins
Integrations
Environment
CLI
Automation
```

---

## 3.5 Extensible

Third-party developers should eventually be able to create:

* Tools
* Plugins
* Integrations
* Providers

without modifying the KuroCode core.

---

## 3.6 Observable

KuroCode should provide visibility into:

* What it is doing.
* Which tool it is using.
* Why an action failed.
* What it changed.
* What commands were executed.
* What permissions were required.

---

## 3.7 Recoverable

KuroCode should be designed around failure recovery.

Failures should not automatically terminate the entire task.

---

## 3.8 Controlled Autonomy

KuroCode can be autonomous, but dangerous operations should have permission and approval mechanisms.

---

```text
├── Tools
```

# 5. Agent Loop

The fundamental KuroCode loop is:

```text
THINK
  ↓
PLAN
  ↓
ACT
  ↓
OBSERVE
  ↓
EVALUATE
  ↓
ADAPT
  ↓
THINK AGAIN
```

Example:

```text
User:
Fix the broken application.

KuroCode:
1. Understand task
2. Inspect project
3. Detect framework
4. Inspect Git status
5. Analyze errors
6. Plan changes
7. Modify files
8. Run tests/build
9. Observe results
10. If failed → diagnose
11. Repair
12. Test again
13. Report result
```

# 6. Application Entry Point

The application must have a clear entry point.

The primary Python entry point is:

```text
src/kurocode/__main__.py
```

This supports:

```powershell
python -m kurocode
```

The package should also expose a CLI executable:

```text
kuro
```

through `pyproject.toml`.

Example:

```toml
[project.scripts]
kuro = "kurocode.cli.app:run"
```

Therefore:

```text
kuro
   ↓
kurocode.cli.app.run()
   ↓
Application Bootstrap
   ↓
KuroCode Runtime
   ↓
Agent
```

# 8. Application Bootstrap

The CLI itself should not contain the entire application.

A bootstrap layer should eventually initialize the runtime.

Responsibilities include:

1. Load configuration.
2. Initialize logging.
3. Initialize security.
4. Initialize provider manager.
5. Initialize memory.
6. Load built-in tools.
7. Load plugins.
8. Load integrations.
9. Detect environment.
10. Create the agent.
11. Start the CLI shell.

Conceptually:

```text
CLI
 ↓
Bootstrap
 ↓
Runtime Components
 ↓
Agent
 ↓
Interactive Session
```

# 9. Development Workflow

KuroCode must be easy to develop from VS Code.

Development environment:

```text
VS Code
   ↓
Python Virtual Environment
   ↓
KuroCode source
   ↓
pip install -e .
   ↓
kuro
```

Create environment:

```powershell
python -m venv .venv
```

Activate:

```powershell
.venv\Scripts\activate
```

Install the project in editable mode:

```powershell
pip install -e .
```

Then run:

```powershell
kuro
```

or:

```powershell
python -m kurocode
```

Because the package is installed using editable mode, source changes are reflected immediately.

The developer does not need to rebuild the application after every code change.

# 13. Core Layer

The `core/` package contains the central agent runtime.

## `agent.py`

Represents the KuroCode agent.

Responsibilities:

* Receive goals.
* Maintain agent state.
* Coordinate reasoning.
* Request plans.
* Execute tools.
* Observe results.
* Evaluate progress.
* Continue or finish.

---

## `orchestrator.py`

Coordinates the major components.

Responsibilities:

* Brain
* Memory
* Tools
* Environment
* Planner
* Evaluator
* Security

It acts as the central coordinator.

---

## `context.py`

Builds the context sent to the brain.

Possible context:

* User request
* Current directory
* Current project
* Git status
* Relevant files
* Previous actions
* Memory
* Environment
* Available tools
* Agent identity

---

## `state.py`

Represents the current state of an agent session.

Example:

```text
IDLE
THINKING
PLANNING
EXECUTING
OBSERVING
EVALUATING
WAITING
FAILED
COMPLETED
```

---

## `goals.py`

Represents user goals and subgoals.

---

## `planner.py`

Converts high-level goals into executable steps.

---

## `evaluator.py`

Determines whether the current result satisfies the goal.

---

## `loop.py`

Implements the agent loop.

---

## `events.py`

Internal event system for communication between components.

# 25. Tool vs Plugin vs Integration

One capability.

```text

```

### Plugin

An installable package containing one or more capabilities.

Example:

```text
YouTube Plugin
```

### Integration

Connection to an external service.

Example:

```text
GitHub Integration

├── Repository tools
├── Issue tools
├── Pull Request tools
└── Release tools
```

# 53. Dependency Direction

The architecture must avoid circular dependencies.

Recommended direction:

```text
CLI
 ↓
Core
 ↓
Brain / Memory / Tools
 ↓
Environment / Infrastructure
```

Important rules:

* Tools must not import `Agent`.
* Brain must not directly execute OS commands.
* CLI should not contain business logic.
* Providers should not know about the CLI.
* Plugins should interact through stable public interfaces.
* Core should orchestrate components rather than implement every capability.

# 76. Final Product Definition

> **KuroCode is a local-first autonomous AI agent runtime for Windows that combines LLM reasoning, computer control, persistent memory, developer tooling, external integrations, extensible plugins, automation, self-healing, and controlled self-improvement through a CLI-first interface.**

Its ultimate purpose is to become an intelligent software layer between the user and their computer.

The user provides the goal.

KuroCode understands the environment, reasons about the task, chooses the appropriate tools, executes actions, observes the results, recovers from failures, remembers useful context, and reports the outcome.

The fundamental philosophy is:

```text
USER
  ↓
GOAL
  ↓
KUROCODE
  ↓
REASON
  ↓
PLAN
  ↓
ACT
  ↓
OBSERVE
  ↓
EVALUATE
  ↓
RECOVER / ADAPT
  ↓
COMPLETE
```

And the long-term vision is:

> **Your computer should not just run your software. It should have an intelligent agent that can work with you.**
