# 2. PRODUCT VISION

KuroCode is a personal AI agent that lives on the user's computer.

Instead of being only a chatbot, KuroCode should be able to:

* Understand the user's goals.
* Understand the computer and current environment.
* Reason using one or more LLM providers.
* Execute actions on the PC.
* Read and modify files.
* Run CMD, PowerShell, and Python.
* Work with Git and development projects.
* Use external APIs and services.
* Remember relevant information.
* Install and use tools/plugins.
* Recover from failures.
* Diagnose and repair problems.
* Automate recurring tasks.
* Improve its capabilities in a controlled way.
* Maintain an identity and configurable personality.
* Operate primarily through a CLI.

**Product one-liner:**

> **KuroCode is your personal AI agent living inside your computer.**

**North Star:**

One intelligent CLI agent that understands the user's goal and computer, chooses the right tools, executes work, observes results, recovers from failures, remembers context, integrates with external services, and safely expands its capabilities.

# 4. PRODUCT PRINCIPLES

## 4.1 Local First

KuroCode should operate primarily on the user's machine. The local machine is the agent's environment.

## 4.2 Provider Agnostic

KuroCode must not depend on a single LLM provider. Possible providers include:

* Gemini
* Groq
* OpenAI
* Anthropic
* OpenRouter
* Ollama
* Custom providers

The agent should be able to switch between providers.

## 4.3 Tool Driven

The LLM should not directly control the computer. Instead:

```text
LLM
 ↓
Decision
 ↓
Tool
 ↓
Execution
 ↓
Result
 ↓
LLM
```

This makes actions observable, testable, permission-controlled, and replaceable.

## 4.4 Modular

Every major subsystem should have a clear responsibility:

```text
Brain
Memory
Tools
Security
Plugins
Integrations
Environment
CLI
Automation
```

## 4.5 Extensible

Third-party developers should eventually be able to create tools, plugins, integrations, and providers without modifying the KuroCode core.

## 4.6 Observable

KuroCode should provide visibility into what it is doing, which tool it is using, why an action failed, what it changed, what commands were executed, and what permissions were required.

## 4.7 Recoverable

KuroCode should be designed around failure recovery. Failures should not automatically terminate the entire task.

## 4.8 Controlled Autonomy

KuroCode can be autonomous, but dangerous operations should have permission and approval mechanisms.




```toml

```

```text
kuro

 ↓
Application Bootstrap
 ↓
KuroCode Runtime
 ↓
Agent
```

Keep `__main__.py` extremely small.

It should delegate to the CLI application instead of containing business logic.

# 48. DEPENDENCY RULES

Maintain strict dependency boundaries.

Recommended direction:

```text
CLI
 ↓
Core
 ↓
Brain / Memory / Tools
 ↓
Environment / Infrastructure
```

Rules:

* Tools must NOT import Agent.
* Brain must NOT execute OS commands directly.
* CLI must NOT contain core business logic.
* Providers must NOT depend on CLI.
* Plugins must use public extension interfaces.
* Core should orchestrate, not implement every capability.
* Avoid circular imports.

# 54. IMPLEMENTATION RULES FOR THE AI CODING AGENT

When generating the project:

1. Create the directory structure exactly as specified.
2. Create all required `__init__.py` files.
3. Create a valid `pyproject.toml`.
4. Implement the `kuro` CLI entry point.
5. Implement `src/kurocode/__main__.py`.
6. Keep `__main__.py` minimal.
7. Keep CLI logic inside `cli/`.
8. Keep agent logic inside `core/`.
9. Keep provider logic inside `brain/`.
10. Keep tool abstractions inside `tools/`.
11. Do not put everything into `agent.py`.
12. Do not create a giant `main.py`.
13. Do not tightly couple the agent to Gemini, Groq, or any specific provider.
14. Use interfaces/abstractions where appropriate.
15. Keep dependencies directional.
16. Make components independently testable.
17. Do not implement future features as fake/mock functionality unless explicitly marked as a placeholder.
18. Do not claim functionality is implemented when it is only a stub.
19. Document unfinished subsystems clearly.
20. Prioritize a working MVP over implementing every future feature at once.

# 57. FINAL DEFINITION

KuroCode is a local-first autonomous AI agent runtime for Windows.

It combines:

```text
LLM Reasoning
+
Computer Control
+
Persistent Memory
+
Developer Tools
+
External Integrations
+
Plugins
+
Automation
+
Self-Healing
+
Controlled Self-Improvement
+
CLI
```

The ultimate goal is to create:

> **A personal AI agent that lives inside the user's computer and can work with the user instead of merely answering the user.**

The fundamental interaction is:

```text
USER
 ↓
GOAL
 ↓
KUROCODE
 ↓
REASON
 ↓
PLAN
 ↓
ACT
 ↓
OBSERVE
 ↓
EVALUATE
 ↓
RECOVER / ADAPT
 ↓
COMPLETE
```

Build KuroCode with this architecture as the foundation, while keeping the implementation incremental, testable, secure, modular, and extensible.
